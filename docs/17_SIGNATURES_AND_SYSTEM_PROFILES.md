# Signature combinations and system profiles

## Why signatures matter

Individual capabilities rarely explain Koali’s distinctiveness. The stronger story is often a **combination**: semantic memory + collaboration + routed work + evidence + offline operation, or structured knowledge + multilingual rendering + public dissemination.

Scenario frontmatter therefore keeps `signature_patterns` and `canon_refs` alongside the editorial usage pattern.

## Common presentation profiles

### Knowledge-intensive profile
Kristal-dominant; Konnaxion supports interpretation and contribution; Orgo is lighter until action begins.

### Collaboration / research profile
Kristal + Konnaxion are strong; Orgo rises when the collective becomes a project; UCKK may appear for teaching or dissemination.

### Operational profile
Orgo-dominant with Kristal context and Konnaxion for escalation, expertise, or cross-team coordination.

### Crisis / field profile
Kristal + Orgo + Konnaxion operate around a rapidly changing shared situation; offline/local and multilingual properties may become decisive.

### Public knowledge profile
Kristal keeps provenance; Konnaxion supports contribution; UCKK turns validated knowledge into media or learning; Orgo can manage production and updates.

### Sovereign / local profile
Local-first, offline-capable, AI-optional operation matters as much as the application workflow itself.

## Reading rule

A profile is a communication aid, not a new canonical module or deployment tier.
